## 6. 本地原版核对

已核对游戏自带 `game_concepts_l_english.yml` 的相关条目，以及地点等级、人口类型、道路、时代、制度、建筑、defines、影响力 auto modifier 等定义。路径、key 与行号记录在[原版证据](../knowledge/gameplay/Vanilla_Evidence.md)，关键文件哈希记录在快照中。

版本证据存在边界：项目目标为 1.4 beta，README 仍写 1.2；同步日志最新为 2026-10-13，记录未附 build/checksum。本文能确认当前镜像内容，不能独立证明其确切游戏构建号或运行结果。

本地文本覆盖了外部材料的若干旧描述：

| 问题 | 本轮处理 |
|---|---|
| 贸易范围是否硬门槛 | 当前百科及 TT103 支持超距可交易但成本增加，覆盖 Recap 3 旧描述 |
| 贸易利润是否等于国库现金 | 原版区分贸易收入、费用和王权分配，主文不按面板利润直接入库 |
| 控制是否决定销售收入 | 依原版拆成财富→税基→征税；纠正 Z05 简化 |
| RGO 是否农民直接工作 | 当前适格类型为劳工／奴隶；检查转职和实际就业 |
| 城市化是否总是更好 | 保留乡村 RGO／食物优势及升级条件，不把城镇→城市说成必有新增 RGO 惩罚 |
| 政治影响力是否全面加速 | 区分百科概括、TT119 预览与本地可见的阶层满意度恢复效果 |
| 军通是否允许拿粮 | 区分 military_access、food_access 与港口权 |
| 接纳制度看国土还是人口 | 当前依据人口传播条件；不说任意 20% 地图有进度即可 |
| 自动化是否必然优秀／糟糕 | Z05、Z08、E11 有分歧；改给就业、投入、利润与政策结果核查办法 |
| 时代和制度是否固定旧日期地点 | 使用当前 age 定义，制度还受游戏规则／DLC 条件影响 |

## 8. 保存与复查

`EU5_Gameplay_Source_Snapshot.json` 只保存来源元数据与内容摘要哈希，不依赖会话临时目录，也不复制整篇第三方正文。哈希用于识别本轮取到的内容，**不是事实准确性的保证**。Wiki 用修订号稳定定位，Steam 用 gid 和 API 的 contents 字段定位。

本轮在 `tmp/eu5_gameplay/` 临时抓取 HTML、wiki 源码与 Steam API 内容后阅读；临时原文和工作脚本不纳入交付。主文、案例、版本说明、原版定位、来源快照和本阅读记录可独立使用，无需保留会话缓存。

更新时应：先核对变动来源与本地 key → 写入适用版本和条件 → 修正对应章节中的冲突 → 更新本记录与快照 → 按 CLAUDE.md 重新生成 BRIEF。若新增视频笔记，明确观看／转录范围与时间戳，禁止仅把元数据状态改为已读。
